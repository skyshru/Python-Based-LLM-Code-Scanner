The Problem

Pattern matching finds syntax. It doesn't find intent.

Traditional SAST tools are fast and deterministic because they match patterns: a regex, an AST rule, a known-bad function call. That works for eval(user_input). It does not work for a handler that returns someone else's order because nobody checked whether the requesting user actually owns it — there is no syntactic pattern for "forgot an authorization check." That flaw, and most of what causes real breaches, lives in logic and intent, not syntax.

The second cost is trust. Rule engines that fire on every stylistic near-miss train teams to stop reading their own security tooling's output. Signal-to-noise ratio, not raw detection count, is usually what kills a SAST rollout.

An LLM reads code closer to how a reviewer does. It can hold intent, not just syntax, in view — and it can tell you why something is wrong, not just that it matched a rule ID.

The Method

Four steps. No dashboard to learn.

01
Point it at code
A single file or a whole repo. Python, JS/TS, Go, Java, Terraform, YAML — it already knows what to skip: .git, node_modules, lockfiles, binaries.
02
It reads like a reviewer
Every file is reviewed by an LLM under a security-engineer system prompt spanning OWASP Top 10, CWE, hardcoded secrets, and cloud/IaC misconfiguration.
03
Findings, not prose
Every result is schema-validated: severity, CWE, exact lines, a working before/after patch. Nothing to parse by hand.
04
Set the bar, wire it in
Choose a severity threshold. It exits 1 when something at or above it is found, 0 when the code is clean.

The Comparison

This doesn't replace Semgrep. It catches what Semgrep can't see.

Rule engines and reasoning engines are good at different things. The honest pitch is to run both.

Rule-based SAST
(Semgrep, Bandit, tfsec)		llm-appsec-scanner
Known syntactic patterns Yes — fast, deterministic Yes
Business-logic & access-control flaws Rarely — no rule for "forgot to check" Yes — reasons about intent
Remediation guidance A rule ID and a link A working before/after patch
Setup & upkeep Rules to write and maintain One prompt, zero custom rules
Speed & determinism Fast, identical output every run Slower — one model call per file
Your Pipeline

It speaks exit codes, not dashboards.

Drop it into a job. It gates the build on its own — no report to babysit.

0
Clean
Nothing at or above your severity threshold. Build proceeds.
1
Findings
Something actionable was found. Build fails — on purpose.
2
Tool error
Missing key, bad target, bad output path. The pipeline broke, not the code.
- name: Run security scan
  env:
    GEMINI_API_KEY: ${{ secrets.GEMINI_API_KEY }}
  run: |
    llm-appsec-scanner \
      --target ./src \
      --output security-report.md \
      --severity-threshold HIGH
